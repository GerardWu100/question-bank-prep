# Developer guide

## Start here

Read README.md for the overview, docs/reference/app-behavior.md for detailed behavior and running, docs/user/question-format.md (with examples/) for bank syntax, and ops/RECOVERY.md for recovery. The original implementation plan remains unchanged as the intended product contract. The app runs natively or from the `app` target of the Dockerfile; the `test` target is the reproducible Linux check. The user explicitly relaxed strict calculator isolation.

The application is a TypeScript workspace: React/Vite in `apps/web`, Fastify in `apps/server`, the AI provider adapters in `apps/ai-runtime`, a disposable Pyodide worker in `apps/calculator`, and an Electron wrapper in `apps/desktop` (its own package and lock file, not an npm workspace). `packages/domain` owns Markdown parsing and grading. Root scripts own reproducible tests, a synthetic scale benchmark, backup/restore, `find-duplicates` (near-duplicate candidates: stem/choice Jaccard plus a case-passage gate, within a topic), and `check-bank` (runs `parseQuestions` on bank files outside the app, for AI extraction loops).

## Durable state and behavior

`Store` uses one SQLite database, WAL and transactions. It also owns the shared write rules, so routes should call these instead of repeating them: `sql()` (cached prepared statements), `receipt()`/`operation()` (idempotency), `mutation()` (operationId optional) and `idempotent()` (operationId required), `putIndexed()` (any write that changes searchable text or `active`; plain `put()` does not touch the search index), `saveNote()` (note plus `id:version` revision), `deactivateFile()`, and `presentQuestion()` (the only serializer that hides keys; its `revealed` flag is what AI hint mode checks). Libraries, operation receipts and schema versions use relational tables; versioned domain objects use JSON records keyed by library and kind. This is smaller than the normalized schema proposed in the plan. FTS5 stores permitted question text and notes separately from answers and solutions. Each search entry's rowid equals its record's rowid (`id` is an UNINDEXED FTS column, so deleting by id scanned the whole index and made imports quadratic); `Store` reindexes once on open when entries are misaligned, as after a VACUUM. `list(libraryId, kind, omit)` drops large fields inside SQLite (`json_remove`) for callers that only count, filter or sort (`QUESTION_TEXT_FIELDS`, a file's `content`); never `put` such a partial record. `setSummaries` lists sets without their items. The partial expression index `records_question_file` serves `questionsInFile` and the per-file label sync; queries must keep the literal `kind='question'` to use it. A commit empties `files` and `identityProposals` of every import preview in its library (all are stale after the generation bump), so preview records do not keep whole banks. Do not make the public practice serializer depend on a client-side hidden-answer flag.

Questions carry `topic` and `source` from `pathLabels(file.path)` in `store.ts` (first folder, file name without `.md`); `syncPathLabels` refreshes them on every folder sync because unchanged files skip import. The overview returns a `catalog` of topic/source/chapter rows with answered and total counts for the practice filters, and set responses come from `presentSet`, which adds `itemStatuses` (one grade per question) for the number strip. The client keeps the view in the URL hash (`#/practice/<setId>`, `#/notes`, …) and pushes a history entry per view change. `Markdown.tsx` hides `\$` from remark-math before parsing, because remark-math would otherwise end a formula at an escaped dollar sign.

Tutor study-note tools (`searchReading`, `listReadingFilesWithSizes`, `readReadingLines`, `runRipgrep` in `reading-routes.ts`, exposed as rg (or search_study_notes when ripgrep is missing; never both), list_files, read_file). Full-mode chats also get get_my_mistakes (per-chapter counts plus wrong/unsure questions), get_my_questions and get_my_notes, each bounded; search_materials returns previews and read_material caps text at 20,000 characters get `readingRoot` through `buildApp` and are offered only outside hint mode. `runRipgrep` spawns `rg` without a shell in the notes folder with stdin closed (with a pipe there, rg given no path searches stdin and hangs until the timeout); only options in `RG_LONG_OPTIONS`/`RG_SHORT_FLAGS` pass (an allow-list: rg has program-running options such as `--pre` and `--hostname-bin`), and absolute paths and ".." are refused. `reading-routes.ts` serves READING_ROOT read-only (Markdown list, Markdown and raster images by path; traversal, symlinks and SVG refused); `Markdown` resolves relative images against it only when given `readingDirectory`, and the client splits long files at #/## headings into sections of at least 150 lines. A reading chat (`readingPath` + `readingTitle` = "N. heading") is reused per section; each message sends that section's text as `material` (capped at 40,000 characters) and the system prompt uses it instead of a question. KaTeX is pinned to the version rehype-katex uses (0.16.47): the stylesheet must match the markup, or subscripts render at full size on the baseline. `Markdown` repairs common `$$` fence slips from converted notes (see `prepareMarkdown`), wraps `&`-aligned display math in `aligned`, renders ```mermaid blocks with a lazily loaded, strict-mode Mermaid, turns `<br>` into breaks and drops HTML comments; other raw HTML stays escaped. Colours are CSS tokens named by role (`--bg`, `--surface`, `--text-muted`, `--accent`, `--good`/`--warn`/`--bad` …) at the top of `style.css`; each holds `light-dark(light, dark)`, so one list serves both themes and `color-scheme` picks the value (system preference, or `[data-theme]` from the header switch). Text tokens are slightly dimmed (dark `--text` #dcdbd7) and keep at least 4.5:1 contrast (WCAG AA) in both themes; check new pairs before adding them. Fonts are self-hosted through `@fontsource-variable` (Inter for text, Source Serif 4 for headings), so the look does not depend on the fonts installed on a device. Font size is the `--font-size` variable set from the header. The accent is a deep, low-saturation slate teal on purpose; keep it low-key. The Materials hash carries the open file and section (`#/materials/<encoded path>/<section from 1>`): a section change replaces the history entry and a new file pushes one, so Back returns to the file read before. `openReading` records each left file's section and scroll offset in `readingSpots` (this session only) and reopens a file there, which also drives the **↩ Back to** button (`previousReading`). History groups chats with `CHAT_GROUPS` (`readingPath` → Materials, `questionId` → Practice questions, else Ask AI); the chips at the top pick one group (`historyView`, a browser preference); `DELETE /chats/:id` calls `store.deleteChats`, which also removes runs and unlinks AI notes, and the route aborts a streaming reply (`activeChats`).

Images: `Markdown` loads a relative image from `/api/reading/file` (Materials, `readingDirectory`) or `/api/material-root/file` (questions, `bankDirectory` = the folder of the question's bank file; `store.question` adds `path`). Both go through `sendStudyFile` in `reading-routes.ts`: allowed types only, no traversal or symlinks, and a sandbox Content-Security-Policy so an SVG's scripts never run. The bank route serves images only, never the bank Markdown.

Login sessions are rows in the SQLite `sessions` table (SHA-256 of the token, expiry), 30 days with sliding renewal on `GET /api/session`, cookie `SameSite=Lax` (the origin hook still refuses cross-site writes). `POST /api/session` allows `LOGIN_ATTEMPTS` (10) per `LOGIN_WINDOW` (15 minutes) per client. `TRUST_PROXY=true` sets Fastify `trustProxy` to `TRUSTED_PROXY_RANGES` (loopback, link-local, private): forwarding headers count only from such a peer, so `request.ip` is the address the proxy saw and `request.protocol` follows X-Forwarded-Proto (cookie `Secure`, HSTS); a public client reaching the app directly cannot fake either. A hop count (`trustProxy: 1`) does not work: this Fastify version trusts nothing for numbers. The `onRequest`/`preValidation` hooks decide "is this an API route" from `request.routeOptions.url` (the matched pattern), never `request.url`: the router decodes the path, so `/%61pi/libraries` reached the handler while skipping every raw-URL check. An `onSend` hook adds `CONTENT_SECURITY_POLICY` (scripts only from the app; inline styles allowed for KaTeX/Mermaid; a route's own policy, such as the file sandbox, wins), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: same-origin` (`no-referrer` would make browsers send `Origin: null`, which the origin check refuses) and HSTS on HTTPS. The Dockerfile `app` stage runs as `USER node`.

`DELETE /notes/:id` removes a note and its search entry (revisions stay for old citations). The readable export is `GET /export/notes?origin=mine|ai` (Markdown); a full backup is the `backup` script. `study-data-routes.ts` owns the round trip: `GET /export/study-data` (JSON, `format: question-bank-prep/study-data`, version 1: per question topic, source, question ID = title without `Question `, optional path/chapter/caseTitle (older files lack them), fingerprint, selection, confidence, answerSequence, flag, note; plus all notes) and `POST /import/study-data` (`content` = that JSON, operationId required). `matchEntries` decides by content first: an entry with a fingerprint matches only questions with that fingerprint (a unique one wins even after a move or renumbering; a same-numbered question with other content never does); several such questions, or an entry without a fingerprint, must narrow to one by location (path, else topic + source, plus question ID, chapter and case title when present). A question chosen by two entries goes only to the one at its location. The rest come back in `unmatched` (no such content here) or `ambiguous` (no unique choice) and change nothing. It replays answers in exported `answerSequence` order with new library sequence numbers, bumps `state.version`/`annotation.version` only on a real change, keeps a local question note when the file has none, and skips notes with the same title and content hash. Questions are matched within the open library only; banks are never imported this way.

Hooks in `app.ts` read route config instead of URL strings: `config.public` skips sign-in, `config.allowWhenArchived` permits writes to an archived library. The overview returns only counts and set summaries; the client asks `POST /sets/preview` for the practice count, so the server's `Store.select` is the single filter implementation.

A question has overall state; each saved set has its own response. `Store.question` and `presentSet` fall back to the overall answer when a set has none, so a new set never looks blank for a question answered elsewhere. A fresh Start (chapter decks, Mistakes/Unsure/Flagged reviews and custom sets) sends `POST /sets` with `reuse: true`: the server runs `Store.select` and reopens the newest set whose filters (key order ignored) and ordered question IDs both equal the current selection (`setWithQuestions` in `app.ts`), else creates one, so a bank change or a new answer that swaps members gives a new set while the old one stays as history. The set list is hidden; source editing and the Focus page are gone from the UI (their server routes remain). Answer writes atomically update both, advance the library sequence once, and store an idempotent receipt. Record versions reject stale tabs. Import key corrections derive grades and normalize confidence without advancing answer recency. Frozen sets retain deleted-source placeholders. "Source order" sorts by file path, then position in the file.

`Resume last session` remembers the last successfully opened set in this browser under `lastPractice:<libraryId>`; the selected library is also a browser preference. Only the set ID is stored locally: its cursor remains in SQLite. Resume and a practice URL restored after reload call `openSet(..., { keepPosition: true })`, preserving the exact saved question even when answered. Normal deck Start/Continue keeps the existing first-unanswered behavior. Resume reuses the set rather than creating one and is disabled when this browser has no valid saved set for the selected library. Practice shows four compact result counters at the bottom of the page, and global ★ Flagged / ✗ Mistakes / ? Unsure buttons at the top (`openDeck` with no topic: those sets ignore the source toggles). The question view pins Previous / position / Next in a sticky `.question-nav` and puts the set title, progress and `QuestionStrip` below the question; `answerOnClick` (browser preference, Settings → Practice) makes a choice click call `answer()` directly. The Guide tab (`Guide.tsx`, lazy chunk) renders `apps/web/src/guide.md` split at `## ` headings, plus the four prompt files and `docs/user/question-format.md` imported with Vite `?raw`, so editing those files updates the in-app guide on the next build; it needs no library. There is no header bar: the nav holds the tabs (and the library picker when there are several libraries); text size, theme, line width (`PAGE_WIDTHS`, caps `main` through `--page-width`) and line spacing (`LINE_SPACINGS`, sets `--line-height` for `.markdown`) live in Settings → Display as browser preferences. A solution's `Intuition (AI)` sub-heading is split off by `Solution` and shown above the source text in an `.intuition` box; the result box colours only its edge and label. On Notes, every card's summary has Delete; the AI notes tab renders `tutorConversation`, and an effect clears a question/reading chat on entering Notes and reloads the question's chat when returning to Practice.

Focus items have one shape: `links: [{questionId, contentVersion, answerVersion, annotationVersion?}]`. `Store.focus()` drops deleted items and derives `stale` from those versions; staleness is never stored. Deterministic refresh items also keep `questionId` to find their previous item.

An `Answer (AI)` heading sets `answerByAI` (part of `CONTENT_FIELDS`, so a source key replacing an AI key makes a new revision); the UI shows it only as a hover tooltip on the Answer line. The parser uses a Markdown syntax tree for headings and retains original content slices. A case passage runs to its first Question heading (so exhibits stay in it) and ends at the next heading of the same or shallower depth. Fingerprints include case, stem and choice semantics, exclude keys/solutions, and preserve numbers/operators.

Re-import identity: an incoming question continues an old one automatically when exactly one same-file question has its fingerprint (ties break on title, chapter and case). Previews report this as `identityProposals[].automatic`; the UI asks only about proposals without one, and an unanswered proposal becomes a new question. A question keeps its `contentVersion` (and writes no new revision) unless fingerprint, key, solution, title, chapter or case title changed. A changed choice meaning cannot reuse the old selected label silently. Re-importing an inactive file with identical bytes reactivates it with the same question IDs (`restoredMatch`): `deactivateFile` records the file's last active questions in `removedQuestionIds`, and each returning question takes the only one of them with equal `CONTENT_FIELDS`; a file removed before that field existed offers all its inactive questions, and a tie makes a new question instead of merging. Matching only active questions (as before) gave a restored file new, unanswered identities. Changed bytes get no reactivation.

## Source ownership

Import reuse checks the material type as well as path and content hash: changing an unchanged file from questions to a note must still update questions and search entries. Hash-based rename detection requires a unique matching file on both sides; multiple identical incoming copies receive distinct file identities.

Uploaded Markdown and immutable revisions live in SQLite. The Materials import sends one file or a whole picked folder (`readMarkdownFiles` in `main.tsx` keeps `.md` files, skips README.md, `.git` and `node_modules`, and drops the picked folder's own name so paths match a configured folder) in one `POST /imports/preview`; the body limit is 64 MiB (`MAX_REQUEST_BYTES`). Choice labels default to `DEFAULT_CHOICE_LABELS` (A–Z) taken in letter order (`inLetterOrder`), so a line like `I. …` inside choice C stays text; a library-configured label set keeps the strict set-membership rule and reports a letter past its last label. Configured-folder imports read existing `.md` files in place. `material-files.ts` rejects traversal/symlinks and checks file hashes; a folder it cannot read is `ROOT_UNAVAILABLE` (409), never an empty folder. `material-routes.ts` rechecks preview bytes, marks removed sources inactive, and exposes journal recovery. `POST /imports/root-sync` (called by the client whenever a library opens) previews and commits the folder in one step, skips the commit when every active local file hash is unchanged, deactivates every local file (one generation bump, uploaded files kept) when the folder scans as empty, accepts warnings, and turns unmatched identities into new questions; structural errors leave the library unchanged and come back as issues. Local source editing is a human route, never an AI tool. Filesystem writes and SQLite commits cannot share one atomic transaction; the durable journal handles that gap. External processes can still race the final rename.

AI notes are distinct records with persistent origin labels and revisions. Original material is not rewritten by AI. Backups capture the imported bytes and database records, not unimported external-file edits or credentials.

## AI boundary

The server's provider is `ConfigurableProvider` (`apps/ai-runtime/api-key.ts`). It reads `<STUDY_DATA_DIR>/ai-settings.json` (`AISettingsFile`, mode 0600, `{connections: [{id, kind: codex|api, baseUrl, apiKey, models[]}]}`) on every call; list order is fallback order. `kind: codex` is `SubscriptionProvider` (`index.ts`, pi-ai `openai-codex-responses`); `kind: api` is `ApiKeyProvider` (Anthropic Messages API on `api.anthropic.com`, else OpenAI-compatible Chat Completions with `reasoning: false` and a `system` message; provider error text is shown with the key stripped). A reply starts on the connection offering the chosen model; an error in `FALLBACK_CODES` before any text or reasoning moves to the next ready connection's first model, and `done` records who answered. All run one shared loop, `streamWithTools` in `index.ts` (text, reasoning, tool rounds, limits). `/api/ai-settings` (GET/PUT the whole list) and `/api/ai-settings/remote-models?connection=<id>` exist only for a `ConfigurableProvider`; keys are write-only (the browser gets `apiKeySaved` and the last 4 characters); `AISettingsFile.update` keeps a saved key only while the connection's base URL is unchanged (otherwise it asks for the key again, so a stolen session cannot redirect the key to another server) and refuses link-local base URLs (`isLinkLocalHost`: 169.254.0.0/16, fe80::/10 and metadata names, with IPv4-mapped IPv6 such as `[::ffff:a9fe:a9fe]` read as its IPv4 address). API-key requests go through `endpointFetch`, which also refuses a host name that resolves to a link-local address and never follows redirects. The ChatGPT sign-in file is `CODEX_AUTH_FILE`, else `$CODEX_HOME/auth.json`, else `~/.codex/auth.json`, read through `codex_auth_file_store.mjs`, an unchanged copy of the canonical store in `one-time-projects/codex-auth-maker`: a file marked `refresh_owner: pi-ai` is refreshed here under a shared lock (servers need no Codex CLI); a Codex CLI file is read only. Codex's `models_cache.json` is not read: offered ChatGPT models are the connection's IDs that the pinned pi-ai catalog knows (default `gpt-6.1-sol`, `gpt-6-luna`). `ModelUsageLimit` (`apps/ai-runtime/usage-limit.ts`) caps model requests for the whole process (rolling hour and day, `AI_MAX_REQUESTS_PER_HOUR`/`_PER_DAY`, defaults 60/300, 0 = off); every provider call, tool rounds and fallback attempts included, takes a slot, and the request times persist in `<STUDY_DATA_DIR>/ai-usage.json`. Docker mounts the sign-in folder `${CODEX_HOME:-~/.codex}` read-write at `/codex`, because a refresh renames a new file into place and takes a lock folder beside it. Account errors disable that connection but leave practice usable.

The practice page and the Ask AI page render the same conversation block (`tutorConversation` in `main.tsx`); under a question it loads that question's saved chat and sends with the active set's ID, which `visibleChat` uses to filter hint-mode messages. The model menu lists every connection's models, each named with its connection (an ID listed twice is served by the highest connection that has it enabled, else shown disabled with the first listing's reason; `modelOwners` in `api-key.ts` decides this for both the menu and the reply, so the name and thinking levels shown are the serving connection's); the chosen model is `library.settings.model` (default `gpt-6.1-sol`), and the client sends it with each message. Set filters accept `sources: string[]` for the Practice source toggles. The client polls `GET /runs/:id` while a reply streams; there is no server-sent-events route. Durable chat runs retain partial text, terminal status, model, source handles and tool summaries. Restart marks unfinished runs interrupted. The hint tool surface omits keys/solutions, previous solved chats and overall responses. Full tutoring can use library-scoped retrieval and bounded calculator calls. AI writes require separate explicit user actions. Source handles resolve retained revisions; their existence does not prove that a model's claim is correct.

Reading chats opened from History or continued from a saved AI note (`continueChat`) first reopen their file and saved section on Materials, so the next reply carries that section's text. When that section no longer resolves (file gone, or its numbered heading changed), the chat opens on Ask AI or Notes with a missing-material notice, and `sendToTutor` refuses any reading chat whose own section is not the open one, so it never attaches another file's text. Practice navigation (`openSet`, `navigate`, `closeSet`, library switch, leaving Practice) takes a new `navigationToken`; `loadQuestion` fetches the question and its chat together and applies them with the set only while its token is the newest, and cursor PATCHes run one at a time from `latestSet`'s version. Browser IDs (operationIds, new AI connection IDs) come from `randomId()` in `api.ts`: `crypto.randomUUID` exists only in secure contexts (HTTPS, localhost), so a plain-HTTP server reached by IP or host name gets a version 4 UUID built from `crypto.getRandomValues`. Root-level reading files appear under General. Restored section indices are validated and clamped after splitting the current file, then the repaired bookmark is saved. Practice arrow-key shortcuts run only while the Practice view is visible.

The calculator runs one job at a time in a fresh child process (`fork` in `apps/calculator/index.ts`, JSON over IPC) with startup/execution timeouts and bounded output. The AST filter in `worker.mjs` is only a first fence (generator frames such as `gi_frame.f_back.f_globals`, or `statistics.sys`, reach the host without underscores). The boundary is Node's permission model: `--permission` with reads limited to the worker script and the Pyodide folder, no writes, child processes, worker threads or add-ons, and an empty environment. `worker.mjs` replaces `process.binding`, which the permission model refuses, with one that returns only `fs` constants (Pyodide's NODEFS reads them at startup). Network access is open and WebAssembly memory is not capped.

## Validation evidence

`docker build --target test -t question-bank-prep-test . && docker run --rm question-bank-prep-test` runs `npm run typecheck`, `npm test`, `npm run build` and `npm run test:e2e` on Node 24. `tests/question-format.test.ts` parses every file in `examples/`, so the format guide fails tests when it drifts from the parser. Browser tests run Chromium against the production build on port 3100 with a fresh temporary database and synthetic reading fixtures. Build first; the suite refuses to reuse an existing server and overrides local password/material settings, so it cannot write test data to the app on port 3000. `scripts/run-browser-tests.mjs` runs each spec file in a separate Playwright invocation by default, giving it a fresh server and rate-limit window. This avoids cumulative test traffic exhausting the unchanged production limit of 300 requests per minute. Explicit arguments, for example `npm run test:e2e -- tests/e2e/resume.spec.ts`, run one focused invocation; use the default command for the whole suite. The tutor payload regression intercepts its request without contacting a provider. Normal UI does not fabricate AI responses. Native install/build logs are in ignored `logs/`.

`tsx scripts/benchmark.ts` imports 10,000 synthetic questions in 100 files and measures indexed search. On the Linux machine (Node 22) on 2026-10-17 the import took 4.5 s (11.7 s before the rowid-keyed index), search p95 was about 8 ms and peak resident memory about 280 MiB; most of the remaining import time is Markdown parsing (about 0.3 ms per question). These are synthetic results, not guarantees for other banks or hardware.

`npm run build` runs `scripts/compress-build.mjs` after Vite, writing `.br`/`.gz` copies that `@fastify/static` serves with `preCompressed`; hashed files under `/assets/` are cached for a year (`immutable`), `index.html` is revalidated. The client loads `Markdown.tsx` (remark, KaTeX) as a lazy chunk behind `Suspense`, prefetched after page load. `/api/reading/file` answers unchanged files with 304 from a size-and-mtime ETag. The question number strip is a memoized `QuestionStrip`, folded note cards and reasoning render Markdown only once opened, and tutor polling reads only the chat (3 s while the tab is hidden) and never replaces a different open chat.

## Open issues and verification limits

Last checked: 2026-10-24 (security sweep), native Linux with Chrome/Chromium; earlier Docker Node 24 (Debian bookworm) and native macOS/Node 26.

- Automated parser tests use synthetic fixtures. The live application now loads a real question bank and reading material, but that browser check is not a complete content audit.
- The complete proposed release matrix is not certified: Firefox/WebKit, physical devices, HTTPS deployment, 100,000-section/chat loads, retrieval grounding quality and provider refresh/revocation scenarios need separate checks. AI inside the Docker image (sign-in folder mount) is untested.
- Local-file save recovery has API routes but no Settings screen yet (see ops/RECOVERY.md).
- Changing choice labels does not reparse files whose bytes are unchanged; re-import after editing them.
- Route bodies are still checked by hand plus a global field-type hook, not per-route Fastify schemas.
- Search indexes whole question/note records rather than heading-based bounded chunks. Large notes and unsegmented Chinese need measured retrieval evaluation before claiming complete search coverage.
- State uses JSON records instead of the plan's normalized schema. Large-library overview/set serialization and chat-history scans may need pagination and more relational indexes at larger loads.
- Subscription reuse uses the adapter's legacy Codex transport, not the newer application-specific token-sharing registration. A minimal live response and a tool round trip succeeded; upstream changes may require an adapter update. A Codex CLI login is read only, so it must be refreshed by Codex; an app-owned (codex-auth-maker) login is refreshed here, but a real refresh has not been exercised yet. Anthropic is verified only to fail over on a bad key; a real Anthropic reply is untested.
- Calculator: the permission-model boundary was checked by hand on Node 22 (unfiltered Pyodide code could not read `/etc/hostname` or `.env`, write, or run `id`); `tests/security.test.ts` covers only the Python filter. Network and WebAssembly memory stay unbounded. Inside Electron (`ELECTRON_RUN_AS_NODE` + `--permission`) it is untested.
- API base URL checks (2026-10-24): `endpointFetch` resolves the host before each API-key request, but the transport resolves it again, so DNS rebinding (an answer that changes between the two lookups) can still reach a link-local address; closing it needs a connection-level lookup hook (an undici `Agent` with a checked `connect.lookup`). Redirects are refused outright, so an endpoint that redirects (for example http to https) fails instead of being followed. The ChatGPT subscription transport uses fixed hosts and is not wrapped.
- KaTeX 0.16.47 is in the range of GHSA-238p-pmpm-9mq7 (needs an existing prototype-pollution bug to matter); the fix is KaTeX 0.19, which needs rehype-katex/remark-math and the CSS rechecked together.
- Mermaid strict mode already runs DOMPurify over its SVG; a second DOMPurify pass with default options stripped the `<foreignObject>` labels, so there is none. The CSP is the second layer.

- Desktop app server mode: `desktop-settings.json` `serverUrl` (an origin) makes `main.cjs` skip the embedded server and load that URL; `connect.html` + `preload.cjs` (contextBridge, only for that window) ask for the address and check `/api/health` before saving. The main window has no preload, so remote pages get no Node access. Navigation stays in the window only for the exact app origin (`new URL(...).origin`, also on `will-redirect`); other links go to the OS only for http(s)/mailto (`EXTERNAL_LINK_PROTOCOLS`); `http://` server addresses are accepted only for private hosts (`isPrivateHost` in `private-host.cjs`, packaged via the `files` list: IP literals are classified first with a `node:net` BlockList of loopback, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7 and fe80::/10, IPv4-mapped forms included; only then names: localhost, one label or `.local`, never with brackets or colons; `tests/desktop-private-host.test.ts`); pages get no permission except clipboard writes. These desktop changes (2026-10-24) passed a syntax check only; no packaged run. Verified 2026-10-18 against the local server on port 3000 (Linux, dev run).
- Desktop app (`apps/desktop`): `npm run build:desktop` bundles `apps/server/src/index.ts` with esbuild into `apps/desktop/build/server.mjs` (better-sqlite3 and pyodide external, installed by the desktop package) and copies the calculator worker and web build beside it. `main.cjs` sets the server's environment (loopback port, no password, data under Electron `userData/data`, `STUDY_WEB_DIR`, folders from `userData/desktop-settings.json` chosen in the File menu), imports the bundle in-process and loads it in one window.
